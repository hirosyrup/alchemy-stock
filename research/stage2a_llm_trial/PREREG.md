# 段階2a: 上方修正のお知らせを LLM に読ませて、始値の後に続く組と戻る組に分かれるか — 事前宣言

宣言日: 2026-11-02 (下書き)。この文書に OK が出るまで、試し読みも集計もしない。OK の後も、質問・分け方・候補・基準を後から変えない。

## なぜやるか

段階1・1b では、数字 (修正率など) だけで選ぶ形はどれも不合格だった。上方修正 (営業利益の今期予想 +10% 以上) を始値で買うと、
学習期間では始値の後に平均 −0.37% 戻った (コスト前)。ただ、平均の中には上がり続けた会社と大きく戻った会社が混ざっている。

修正の **理由** (本業が強いのか、一度きりの要因か) は数字には出ず、お知らせの文章に書いてある。
LLM にそれを読ませて2つの組に分けると、始値の後の値動きがはっきり分かれるかを確かめる。
読む力の高いモデルで分かれなければ、安いモデルでもまず分かれない。分かれたら、本番で使うモデルで同じことが言えるかを別に確かめる。

## 対象

- 段階1の U10 (上方修正を買う) で、**学習期間 (2016-11 〜 2021-10) に売買できたもの** のうち、
  同じ入る日の開示の中に **業績予想の修正のお知らせ** (J-Quants の財務情報の種類が `EarnForecastRevision`) があり、その PDF が取れているもの (約1,500件)
- 決算短信の中で予想を変えただけのもの (別のお知らせが無いもの) は、ページ数が多いので今回は外す
- 読ませるのはそのお知らせの PDF の文字だけ (最初の3ページまで)。株価・その後の出来事は渡さない
- 文字起こしは **pymupdf4llm** (PLAN.md §6.2 の本命)。太字・取り消し線などの印 (`**` `~~` など) は消す。
  PDF を画像のまま渡すと社名を伏せられないので、文字にしてから伏せる

## 伏せるもの

- 社名 (その日の銘柄の一覧の日本語名・英語名、「株式会社」を外した形も)、証券コードは「当社」「XXXX」に置き換える
- 年は「X年」に置き換える (西暦・令和・平成とも)。月・日は残す (決算期が何月かは読みに要る)
- それでも分かってしまう場合があるので、下の質問5で毎回「どの会社か分かるか」を答えさせる

## 読ませ方

- モデル: Claude Code のサブエージェント (Claude Opus 5.5、知識は 2026年6月ごろまで)
- サブエージェントには、伏せた文字のファイルを読むことと、答えを書くことだけをさせる。ウェブ検索やほかのデータを見ることは禁止する
- 1つのサブエージェントに 25件ずつ渡す。1件ごとに独立に答えさせる (前の件の答えを参考にしない)
- 質問 (この文面のまま渡す):

```
これは日本の上場会社が出した「業績予想の修正に関するお知らせ」です。社名・証券コード・年は伏せてあります。
書かれている内容だけをもとに、次の質問に答えてください。株価やこの後の出来事について知っていることは使わないでください。

1. 営業利益の予想を引き上げた主な理由はどれですか (1つ)
   A: 本業の需要が強い (売上や受注が想定より伸びた、値上げが通った、販売の数量が増えた)
   B: 費用が想定より少ない (コスト削減、経費が使われなかった、費用の時期がずれた)
   C: 一時的な要因 (一回限りの大口の案件、為替、売上の前倒し、会計上の要因、補助金など)
   D: 書かれていない・判断できない
2. その理由は、来期以降も続きそうですか (続く / 一時的 / 判断できない)
3. 修正後の予想は、まだ控えめに見えますか (控えめ / 妥当 / 判断できない)
4. 1 と 2 の根拠になった文を、お知らせから1〜2文そのまま抜き出してください
5. この会社がどこか分かりますか (分かるなら社名、分からなければ「分からない」)
```

- 答えは1件ごとに JSON で残す (質問の番号ごとの答えと、読んだ書類の番号)

## 組の分け方 (答えから機械的に決める)

- **続く組**: 質問1が A、かつ質問2が「続く」
- **戻る組**: 質問1が B か C、または質問2が「一時的」
- どちらでもない: それ以外 (質問1が D、質問2が「判断できない」など)
- 質問3は報告するだけで、組の分け方には使わない

## 試し読み (100件) — 値動きは見ない

1. 対象からランダムに100件 (乱数の種 0) を選び、上の読ませ方で答えさせる
2. 見るのは次の3つだけ。**このとき値動き・成績は一切計算しない**
   - 答えの形が崩れていないか (5つの質問すべてに決まった選択肢で答えているか)
   - 100件のうち10件をもう一度読ませて、組の分け方が同じになる割合 (ぶれ)
   - 1件あたりの使用量と時間 → 全件 (約1,500件) でどのくらいになるかの見積もり
3. 結果をユーザーに報告し、**全件に進むかの OK をもらう**。答えの形の直し (選択肢の書き方など) が要るときは、
   直した内容をこの文書に追記してから全件に進む。質問の中身は変えない

## 候補 (2つ) と成績の付け方

- **CONT (続く組を買う)**: 始値で買い、その日の引けで手放す
- **REV (戻る組を売る)**: 始値で売り、その日の引けで買い戻す (貸借銘柄だけ)
- 入れない日、1回の成績 (TOPIX の動きを引く)、コスト (1往復 0.2%、報告は 0% / 0.2% / 0.4%)、売りの貸株料は段階1と同じ
- 全件の答えがそろってから、1回だけ集計する

## 評価の単位・期間・基準

- 1日 = 1観測 (その日に入った全部の平均、入ったものが無い日は 0)、年換算シャープレシオ = 1日の平均 ÷ 1日の標準偏差 × √245 (段階1と同じ)
- 範囲: 20営業日のブロックでブートストラップ (1万回)、2候補分の補正をして **97.5% 範囲**
- 期間: **学習期間だけ** (読ませたのが学習期間の開示だけなので)
- **次 (検証期間の開示を読ませる段階) に進む条件**: 候補ごとに
  1. 1日の平均 > 0 (コスト 0.2% 込み)
  2. 「どの会社か分かった」ものを除いても、1日の平均 > 0 (コスト 0.2% 込み)
- 報告: 段階1と同じ項目、組ごとの件数、1回あたりの平均の 続く組 − 戻る組 の差とその範囲、どちらでもない組の平均、
  どの会社か分かった割合、質問3 (控えめか) ごとの平均 (報告だけ)、ランダム対照 (同じ対象から同じ回数を選んで同じ向きに売買)

ここで通っても「いける」とはしない。検証期間の開示を読ませる段階、金庫、そして **モデルの知識の締め切り (2026年6月ごろ) より後の開示** での確認を、
それぞれ別の宣言で行う。

## 先に書いておく限界 (正直に)

- **モデルが過去の答えを知っている恐れ**: 社名・コード・年を伏せても、事業の中身や数字から会社が分かることがある。
  質問5で分かった割合を測り、分かったものを除いた成績も条件に入れるが、「分からない」と答えても実は覚えている可能性は消せない
- 本番で毎日動かすモデル (API で呼べる安いもの) とは別のモデルで読ませている
- 決算短信の中で予想を変えただけのものは外しているので、上方修正全体の結果ではない
- 学習期間の U10 は、段階1で「始値の後に平均 −0.37%」と見ている。組に分けた後の結果は見ていない
- 戻る組の売りは貸借銘柄だけなので、戻る組の件数が少なくなるかもしれない
- 学習期間だけの約1,500件 (組に分けるとさらに少ない) なので、範囲は広くなりやすい
